# Native execution contracts

The assembly/package is `Zeroshot.Client`; the scaffold project path remains `src/Zeroshot.Sdk`. Public contracts use `Zeroshot.Native.Contracts`, the local serializer/schema API uses `Zeroshot.Native`, and `PreparedSubmission` uses `Zeroshot`.

`coverage.json` is the binding ledger for native **10.9.0**, source **75ae54b6693b6ae4cedeedd37a79ce3919d9a8fa**. Every named operation has an owner issue, endpoint/auth prerequisites, type references and evidence status. HTTP discovery is implemented by `NativeClient.ForHttp` and `Target.DiscoverAsync`; see [transport usage and ownership](../http/README.md). Other binding rows remain explicit about their evidence. `native-inventory.md` is the pinned #13 inventory, copied from repository commit **3c64d3ba39ddd8599b748e5938cba35bc1026e11**; its source links supply the detailed per-operation type closure and requirements. Notification bindings, implicit UI/history HEAD routes, local stream bindings, advertised-only gaps and compiled schema data are distinct from ordinary request operations. Binding owners must update their row when implementation and verification arrive; source inventory alone is not conformance evidence.

`type-closure.json` lists the complete graph/payload/worker/artifact/submission schema closure implemented here. Native scalar domains that schemas inline also have C# value types; ordinary lists/maps use immutable .NET collections. The checked-in models are regenerated by `python3 tools/generate-contracts.py`, using only the checked-in schema. Python is a development tool, never a consumer/runtime dependency. OECP inspection and complete run watch/log contracts and their source-backed schema closure are in `Contracts/Oecp.cs`, `Contracts/Subscriptions.cs` and `Schemas/oecp.schema.json`; see [OECP usage](../oecp/README.md). Other response/event contracts belong to their later operation issues.

Use `NativeJson.SerializeUtf8` and `DeserializeUtf8<T>` for validated contracts. Raw `System.Text.Json` is not the contract validation API. Tagged alternatives use typed derived records. `Optional<T>` distinguishes omission from a present value, including explicit null where the field admits it; the serializer preserves that choice instead of reproducing native normalization/default elision. Its default is omitted. Unrestricted JSON appears only in native-authored arbitrary-value positions such as initial input and worker output/diagnostics. Common `RunId`, `Cursor` and `SubscriptionId` are opaque strings; the prepared HTTP envelope additionally requires canonical UUIDv7 identity. Unknown fields follow native rules (strict run DTOs; open legacy cluster/result and RPC error objects); arbitrary authored input remains open.

`PreparedSubmission.Create(RunId, RunSubmission)` captures an immutable snapshot. `ImportUtf8` validates the exact `{runId,submission}` envelope and owns a copy of its original bytes; `ExportUtf8` returns a fresh copy. Legal property order, whitespace, escape spelling and runtime aliases survive exact import/export. Typed runtime serialization emits canonical sizes (`tiny` → `small`, `standard` → `medium`). No source resolution, identities, keys or authored content are regenerated. Outer connection values, resolvers and GitHub tokens cannot enter this envelope. **Authored inputs, instructions and scripts can still contain sensitive data.** Default model formatting and contract errors omit authored values; explicit serialization/export intentionally exposes them to the caller. Storage, approval and send-time credentials remain consumer responsibilities.

Validation uses the pinned schema through JsonSchema.Net and native deserializer corrections: UTF-8 versus Unicode scalar bounds; source branch/repository rules; map-key restrictions; aggregate declared-connection names; runtime aliases; integral floating JSON spellings; descriptor-only collection restrictions. Schema regex end anchors are made exact. `RuntimeEnvironment.validate()` in native is separate from deserialization: reserved names, script/variable preparation limits and environment overlap are admission checks, and remain native. Graph validity, worker resolution, template expansion, native-normalized deduplication hashes and execution are also native responsibilities. The library does not claim those checks passed.

The generated `compiled-ir.schema.json` is exposed as local data by `NativeSchemas.ExportCompiledIrUtf8()`. It does not imply a compilation operation. Native schema assets retain the upstream MIT notice in `src/Zeroshot.Sdk/Schemas/NATIVE-LICENSE`, also included in the package.

Golden fixtures derive from pinned protocol source/tests, expanded across all graph node, payload, guard/join, provider and runtime alternatives, plus tagged diagnostic paths and their u32 index boundaries. They establish wire-shape/retention behavior, not graph execution. The external package consumer at `examples/ContractsConsumer` creates, exports and reimports a request without network I/O, Python or a native executable.

The standalone `examples/DiscoveryConsumer` reads an existing target using only the packed package. The independently runnable `tools/native-witness/run.sh` verifies pinned stock-native discovery and fixed-route HEAD refusal with isolated state; it records source provenance and the actual executable checksum. It also proves session acquisition, WebSocket initialization, populated inventory, exact run/source status, unsupported protocol rejection and native empty cluster get. The terminal runtime failure proves inspection, not successful provider execution.

`Contracts/TargetSubmission.cs` adds the source-backed target HTTP request, receipt,
static connection values and resolver closure absent from the generated OECP schema.
`Target.SubmitAttemptAsync` uses the same bounded HTTP operation for typed and retained
requests; see [attempt evidence and classification](../http/README.md#direct-submission-attempts).
`examples/SubmissionConsumer` extends the real-native packed-package witness with
complete asset admission, contained-provider normalization, normalized deduplication,
exact retained replay and proposed versus acknowledged identity. Native admission
and conflict errors are also checked. No SDK identity hash is introduced.

`examples/ObservationConsumer` proves complete native watch/log history replay,
records produced after both establishments, and exact-run/source observation after
a target restart. A native setup hook supplies safe logs and a controlled terminal
setup failure without provider credentials. Both server-close cursors and last
caller-delivered cursors remain available independently.

`Contracts/Connections.cs` maps hosted connection-management requests, summaries
and results. `NativeClient.Connections` binds list/set/delete on validated hosted
discovery; see [hosted connection records](../http/README.md#hosted-connection-records).
These bindings have controlled-authority evidence only.
