# Migrating from 0.1 to 0.2

`0.2.0-preview.1` follows `0.1.0-preview.1`. Read the required changes first. The other
sections change behaviour that well-behaved callers and stock native targets do not reach.

## Required changes

### Move to native Zeroshot 10.10.0

The SDK supports native 10.10.0 at source `3ee1192cec359a0b997f464e703a936e8b67d63c`
only. A client configured with the 10.9.0 binding refuses every run operation as
`NativeBindingProblem.Mismatched`, and nothing is sent.

1. Upgrade the target to the stock 10.10.0 release.
2. Change every caller-supplied binding, run reference and CLI configuration to
   `"release": "10.10.0"` and the new source revision.

Do both at the same time. Run references saved with the 10.9.0 binding are refused by a
0.2 client. No native contract changed between the two releases, so there is nothing else
to migrate in submitted or received data.

### `NativeSchemas.NativeVersion` and `SourceRevision` are no longer constants

Both are now `static readonly` fields, so code always reads the value of the loaded
`Zeroshot.Client`. Code that used them where C# requires a constant no longer compiles:
a `const` field, an attribute argument, a `switch` case label or a default parameter value.
Make that code `static readonly`, or move the value out of the constant context.

### `OecpConnection.InitializeAsync` takes no `InitializeParams`

The overload is now `InitializeAsync(OecpRequest? request = null, CancellationToken
cancellationToken = default)`. It always sends the SDK's protocol version,
`openengine.cluster/v1`. Remove the first argument. Native accepts no other version, so
there is no replacement for sending one.

### `RunSize` rejects `tiny` and `standard`

Submissions and `PreparedSubmission.ImportUtf8` now accept only `small`, `medium` and
`large`. Replace `tiny` with `small` and `standard` with `medium` in stored requests before
you import them. Native keeps the old names only to reopen runs it stored before the
rename, and never sends them.

## Stricter validation

These inputs were accepted in 0.1 and are now rejected as invalid native contracts. Native
emits none of them.

- A repeated known field in a dashboard contract or inside an item of a target HTTP array,
  and a `null` item in a history array.
- A nested record that breaks its own contract rules. The rules used to run only on the
  root record or where a parent forwarded them.
- A `HistoryPage`, `RunHistoryList` or `RunDefinition` decoded through
  `NativeJson.DeserializeUtf8` that breaks its record rules. The bindings already applied
  these rules.

## Exception changes

- Cancelling an HTTP operation throws `NativeHttpOperationCanceledException`, an
  `OperationCanceledException` that carries `CorrelationId` and `SendStarted`.
  `catch (OperationCanceledException)` still catches it.
- A supplied `HttpClient` with a default `Authorization` header is refused with
  `ArgumentException` by every operation. Before, discovery, session, history, dashboard
  and private exports reported `NativeHttpException` (Transport).
- Every HTTP operation on a disposed client throws `ObjectDisposedException` before it
  checks its arguments.
- Invalid use throws synchronously from reads and faults the task of attempts. This moved
  for `HostedRuns.ForceAsync`, both `SubmitAttemptAsync` overloads and discovery's disposed
  check.
- History `Head*` methods throw `ArgumentNullException` for a null discovery, not
  `NullReferenceException`.
- A TCP connect stopped by the handler's own connect timeout reports a `Deadline` failure
  at `Connect`, as documented. Before, it could report `Transport`.

## Additions

- `TransportOptions.TrustedRootCertificatePath` names a PEM root that HTTPS target
  certificates must chain to. It is reread for every new connection.
- `NativeHttpOperationCanceledException`, described above.
